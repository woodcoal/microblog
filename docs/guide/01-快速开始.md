# 第一章：快速开始

本章帮助你快速理解 DaLi.Lens 的核心概念，并完成首次 API 调用。

---

## 1.1 什么是 DaLi.Lens

DaLi.Lens 是一个 **AI 推荐与搜索中间件服务**。你的网站通过调用 DaLi.Lens 的 API，可以实现：

- **文档入库**：将你的内容推送给 DaLi.Lens，系统自动完成分块、向量化、摘要生成
- **个性化推荐**：根据用户行为画像，返回最匹配用户兴趣的内容
- **知识库问答**：用户提问，系统基于已入库文档生成回答
- **兴趣评分**：评估用户对某篇内容的感兴趣程度

> **核心理念**：你只需要关心"推送内容"和"获取结果"，所有 AI 处理逻辑由 DaLi.Lens 在后台完成。

---

## 1.2 前置准备

在开始集成之前，你需要从管理员处获取以下信息：

| 项目         | 说明                 | 示例                          |
| ------------ | -------------------- | ----------------------------- |
| **服务地址** | DaLi.Lens 的部署 URL | `https://api.your-domain.com` |
| **API Key**  | 你的渠道密钥         | `dll_a1b2c3d4e5f6...`         |

> API Key 由管理员在后台创建渠道时生成，每个渠道拥有独立的 Key。**请妥善保管，不要暴露在前端代码中。**

---

## 1.3 认证方式

所有外部 API 请求通过 HTTP Header 携带 API Key 进行认证：

```
Authorization: Bearer {你的API Key}
```

系统会自动从 API Key 解析出你所属的渠道，你**不需要**在请求中传递渠道 ID。

### 前端安全建议

由于 API Key 是敏感信息，**强烈建议**通过你自己的后端代理转发请求，而非直接在前端调用 DaLi.Lens API：

```
用户浏览器 → 你的后端（存储 API Key）→ DaLi.Lens API
```

如果必须前端直连，请确保：

- API Key 仅在内部系统使用，不面向公网暴露
- 配合 CORS 策略限制来源域名

## 1.4 统一响应格式

所有 API 返回统一的 JSON 结构，你只需要解析一种格式：

### 成功响应

```json
{
  "success": true,
  "data": { ... },
  "error": null
}
```

### 失败响应

```json
{
	"success": false,
	"data": null,
	"error": {
		"code": "ERROR_CODE",
		"message": "人类可读的错误描述"
	}
}
```

### 前端通用解析逻辑

```javascript
async function callApi(url, options = {}) {
	const response = await fetch(url, {
		...options,
		headers: {
			Authorization: `Bearer ${API_KEY}`,
			'Content-Type': 'application/json',
			...options.headers
		}
	});

	const result = await response.json();

	if (result.success) {
		return result.data;
	}

	// 业务层失败处理
	throw { code: result.error.code, message: result.error.message };
}
```

## 1.5 分页约定

所有列表接口使用统一的分页参数：

| 参数       | 类型 | 默认值 | 说明               |
| ---------- | ---- | ------ | ------------------ |
| `page`     | int  | 1      | 页码，从 1 开始    |
| `pageSize` | int  | 20     | 每页条数，最大 100 |

分页响应格式：

```json
{
  "success": true,
  "data": {
    "items": [ ... ],
    "totalCount": 156,
    "page": 1,
    "pageSize": 20
  }
}
```

### 前端分页组件示例

```javascript
async function fetchDocuments(page = 1, pageSize = 20) {
	const data = await callApi(`${BASE_URL}/api/documents?page=${page}&pageSize=${pageSize}`);
	return {
		items: data.items,
		total: data.totalCount,
		totalPages: Math.ceil(data.totalCount / pageSize)
	};
}
```

## 1.6 健康检查

在集成前，先调用健康检查接口确认服务可用：

```
GET /api/health
```

> 此接口无需认证。

```javascript
async function checkHealth() {
	const response = await fetch(`${BASE_URL}/api/health`);
	const result = await response.json();

	if (result.success && result.data.status === 'healthy') {
		console.log('服务正常');
	} else {
		console.warn('服务异常:', result.data.status);
	}
}
```

响应示例：

```json
{
	"success": true,
	"data": {
		"status": "healthy",
		"version": "1.0.0",
		"checks": {
			"database": { "status": "healthy" },
			"qdrant": { "status": "healthy" }
		}
	}
}
```

| status 值   | 含义                   | HTTP 状态码 |
| ----------- | ---------------------- | ----------- |
| `healthy`   | 全部正常               | 200         |
| `degraded`  | 部分服务降级（仍可用） | 200         |
| `unhealthy` | 核心服务不可用         | 503         |

## 1.7 集成流程总览

一个典型的前端集成流程如下：

```
1. 推送内容 → POST /api/documents
2. 确认处理完成 → GET /api/documents/{externalId}
3. 注册用户 → POST /api/users
4. 获取推荐 → GET /api/public/recommendations/{userId}
5. 用户交互反馈 → POST /api/users/{userId}/feedback
6. 反馈积累后推荐自动优化
```

后续章节将逐一详解每个步骤。

## 1.8 常用错误码速查

| HTTP 状态码 | 错误码              | 含义               | 前端处理建议   |
| ----------- | ------------------- | ------------------ | -------------- |
| 400         | `VALIDATION_ERROR`  | 参数校验失败       | 检查请求参数   |
| 401         | `UNAUTHORIZED`      | API Key 无效或缺失 | 检查认证配置   |
| 403         | `FORBIDDEN`         | 渠道已禁用         | 联系管理员     |
| 404         | `NOT_FOUND`         | 资源不存在         | 提示用户或跳转 |
| 409         | `CONFLICT`          | 资源重复           | 提示已存在     |
| 413         | `CONTENT_TOO_LARGE` | 内容超限           | 限制输入长度   |
| 502         | `*_UNAVAILABLE`     | 外部服务不可用     | 稍后重试       |
