# 第六章：兴趣评分

兴趣评分接口用于评估用户对某段内容的感兴趣程度。你可以利用评分结果对内容进行排序、过滤或标记，实现更精细的内容分发策略。

---

## 6.1 核心概念

### 评分原理

系统将用户画像向量与待评分内容向量进行相似度计算，输出一个 0~1 之间的评分：

- **高分（接近 1）**：用户很可能对这段内容感兴趣
- **低分（接近 0）**：用户可能对这段内容不感兴趣

### 算法选择

| 算法             | 说明               | 适用场景                 |
| ---------------- | ------------------ | ------------------------ |
| `vector`（默认） | 基于向量余弦相似度 | 通用场景，精度最高       |
| `keyword`        | 基于关键词匹配     | 关键词明确的场景，速度快 |
| `hybrid`         | 向量 + 关键词混合  | 兼顾精度和覆盖率         |

### 前置条件

- 用户需有一定量的反馈记录（否则画像为空，评分无意义）
- 待评分内容需要是文本（系统会实时向量化）

---

## 6.2 兴趣评分接口

### 接口

```
POST /api/public/interest-score
```

### 请求体

```json
{
	"userId": "user_12345",
	"content": "这是一篇关于 Kubernetes 集群高可用部署的深度指南...",
	"algorithm": "vector"
}
```

| 字段        | 类型   | 必填 | 说明                                             |
| ----------- | ------ | ---- | ------------------------------------------------ |
| `userId`    | string | 是   | 你的业务用户 ID                                  |
| `content`   | string | 是   | 待评分的内容文本                                 |
| `algorithm` | string | 否   | 算法选择：`vector`（默认）/ `keyword` / `hybrid` |

### 成功响应

返回评分结果，包含 `score` 字段。

### 错误响应

| 场景                   | 错误码                      | HTTP 状态码 |
| ---------------------- | --------------------------- | ----------- |
| userId 或 content 为空 | `VALIDATION_ERROR`          | 400         |
| 不支持的算法           | `ALGORITHM_NOT_IMPLEMENTED` | 501         |
| 向量化服务不可用       | `EMBEDDING_UNAVAILABLE`     | 502         |

## 6.3 前端集成示例

### 基础评分函数

```javascript
/**
 * 评估用户对内容的兴趣评分
 * @param {string} userId - 业务用户 ID
 * @param {string} content - 待评分内容
 * @param {string} [algorithm='vector'] - 算法选择
 * @returns {Promise<Object>} 评分结果
 */
async function scoreInterest(userId, content, algorithm = 'vector') {
	return await callApi(`${BASE_URL}/api/public/interest-score`, {
		method: 'POST',
		body: JSON.stringify({ userId, content, algorithm })
	});
}
```

### 批量评分（串行）

```javascript
/**
 * 对多个内容项进行兴趣评分
 * @param {string} userId - 业务用户 ID
 * @param {Array<{id: string, content: string}>} items - 待评分内容列表
 * @returns {Promise<Array>} 带评分的结果列表
 */
async function batchScoreInterest(userId, items) {
	const results = [];

	for (const item of items) {
		try {
			const scoreResult = await scoreInterest(userId, item.content);
			results.push({ ...item, score: scoreResult.score });
		} catch (err) {
			results.push({ ...item, score: null, error: err.code });
		}
	}

	// 按评分降序排列
	return results.sort((a, b) => (b.score ?? 0) - (a.score ?? 0));
}
```

## 6.4 典型场景

### 场景一：内容流排序

根据用户兴趣对内容列表重新排序，高分内容优先展示。

```javascript
async function renderPersonalizedFeed(userId, articles) {
	// 对每篇文章进行兴趣评分
	const scored = await batchScoreInterest(
		userId,
		articles.map((a) => ({ id: a.id, content: `${a.title} ${a.summary}` }))
	);

	// 按评分排序后渲染
	const sorted = scored.filter((s) => s.score !== null).sort((a, b) => b.score - a.score);

	renderArticleList(sorted.map((s) => articles.find((a) => a.id === s.id)));
}
```

### 场景二：内容推荐标记

在内容卡片上标注"为你推荐"标签。

```javascript
async function markRecommendedItems(userId, items) {
	const THRESHOLD = 0.7; // 推荐阈值

	const results = await Promise.all(
		items.map(async (item) => {
			try {
				const { score } = await scoreInterest(userId, item.title + ' ' + item.summary);
				return { ...item, isRecommended: score >= THRESHOLD, score };
			} catch {
				return { ...item, isRecommended: false, score: null };
			}
		})
	);

	return results;
}
```

### 场景三：通知/推送过滤

只向用户推送高兴趣度的内容通知。

```javascript
async function filterNotificationsForUser(userId, notifications) {
	const PUSH_THRESHOLD = 0.8;

	const scored = [];
	for (const n of notifications) {
		try {
			const { score } = await scoreInterest(userId, n.content);
			if (score >= PUSH_THRESHOLD) {
				scored.push({ ...n, score });
			}
		} catch {
			// 评分失败时仍推送
			scored.push(n);
		}
	}

	return scored;
}
```

## 6.5 性能与成本建议

1. **避免高频调用**：每次评分都需要实时向量化，延迟约 200-500ms
2. **使用摘要而非全文**：传入 `title + summary` 而非完整 `content`，减少向量化时间
3. **缓存评分结果**：对同一用户 + 同一内容的评分结果进行前端缓存
4. **并行请求**：对多个内容评分时，可并行发起请求（注意服务端并发限制）
5. **降级策略**：评分服务不可用时，回退到推荐接口或按时间排序

```javascript
// 带缓存的评分函数
const scoreCache = new Map();

async function scoreWithCache(userId, content, algorithm = 'vector') {
	const cacheKey = `${userId}:${hashContent(content)}:${algorithm}`;

	if (scoreCache.has(cacheKey)) {
		return scoreCache.get(cacheKey);
	}

	const result = await scoreInterest(userId, content, algorithm);
	scoreCache.set(cacheKey, result);

	// 缓存 10 分钟后失效
	setTimeout(() => scoreCache.delete(cacheKey), 10 * 60 * 1000);

	return result;
}

function hashContent(content) {
	// 简单哈希，用于缓存 key
	let hash = 0;
	for (let i = 0; i < content.length; i++) {
		hash = (hash << 5) - hash + content.charCodeAt(i);
	}
	return hash.toString(36);
}
```
