# 第七章：反馈系统

反馈是推荐系统持续优化的燃料。用户对内容的每一次交互（点击、点赞、收藏、不感兴趣等）都会更新用户画像，使后续推荐更加精准。

---

## 7.1 核心概念

### 反馈动作

| 动作       | 权重 | 效果                   | 典型触发              |
| ---------- | ---- | ---------------------- | --------------------- |
| `click`    | +0.1 | 用户向量向文档向量偏移 | 用户点击了推荐卡片    |
| `like`     | +0.3 | 用户向量向文档向量偏移 | 用户点赞/收藏         |
| `complete` | +0.5 | 用户向量向文档向量偏移 | 用户阅读完毕/完成学习 |
| `dislike`  | -0.2 | 用户向量远离文档向量   | 用户标记"不感兴趣"    |

> `like` 和 `complete` 是强正向信号，`click` 是弱正向信号，`dislike` 是负向信号。

### 画像更新机制

每次反馈提交后，系统会实时更新用户画像向量：

- 正向反馈：用户向量朝文档向量方向偏移（偏移量 = 权重 × 差值）
- 负向反馈：用户向量远离文档向量

这意味着**反馈越多，推荐越准**。

## 7.2 提交反馈

### 接口

```
POST /api/users/{userId}/feedback
```

### 请求体

```json
{
	"documentId": "article_12345",
	"action": "like"
}
```

| 字段         | 类型   | 必填 | 说明                                                |
| ------------ | ------ | ---- | --------------------------------------------------- |
| `documentId` | string | 是   | 外部文档 ID（你定义的 ID，非系统 ID）               |
| `action`     | string | 是   | 反馈动作：`click` / `like` / `dislike` / `complete` |

### 响应

```json
{
	"success": true,
	"data": { "success": true }
}
```

### 错误响应

| 场景           | 错误码             | 说明                        |
| -------------- | ------------------ | --------------------------- |
| userId 为空    | `VALIDATION_ERROR` | 检查路径参数                |
| 无效的反馈动作 | `INVALID_ACTION`   | action 不在允许列表中       |
| 文档不存在     | `INVALID_ACTION`   | documentId 对应的文档不存在 |

### 接口

```
GET /api/users/{userId}/feedback?page=1&pageSize=20
```

## 7.4 前端集成示例

### 基础反馈函数

```javascript
/**
 * 提交用户反馈
 * @param {string} userId - 业务用户 ID
 * @param {string} documentId - 外部文档 ID
 * @param {string} action - 反馈动作：click / like / dislike / complete
 */
async function submitFeedback(userId, documentId, action) {
	return await callApi(`${BASE_URL}/api/users/${userId}/feedback`, {
		method: 'POST',
		body: JSON.stringify({ documentId, action })
	});
}
```

### 防抖点击反馈

```javascript
// 点击反馈应做防抖处理，避免短时间内重复提交
const feedbackTimers = {};

async function debouncedClickFeedback(userId, documentId, delay = 1000) {
	const key = `${userId}:${documentId}:click`;

	// 清除上一次的定时器
	if (feedbackTimers[key]) {
		clearTimeout(feedbackTimers[key]);
	}

	// 延迟提交，如果用户快速滑动则跳过
	feedbackTimers[key] = setTimeout(async () => {
		try {
			await submitFeedback(userId, documentId, 'click');
		} catch (err) {
			// 反馈失败静默处理，不影响用户体验
			console.warn('反馈提交失败:', err.message);
		}
		delete feedbackTimers[key];
	}, delay);
}
```

## 7.5 典型场景

### 场景一：推荐卡片点击

用户点击推荐内容时上报 `click` 反馈。

```javascript
async function onRecommendationClick(userId, articleExternalId) {
	// 防抖提交点击反馈
	debouncedClickFeedback(userId, articleExternalId);

	// 跳转到文章详情
	navigateToArticle(articleExternalId);
}
```

### 场景二：点赞/收藏按钮

```javascript
async function onLikeButtonClick(userId, articleExternalId, isLiked) {
	try {
		if (isLiked) {
			await submitFeedback(userId, articleExternalId, 'like');
			showToast('已收藏');
		} else {
			await submitFeedback(userId, articleExternalId, 'dislike');
			showToast('已取消');
		}
	} catch (err) {
		showToast('操作失败，请重试');
	}
}
```

### 场景三：阅读完成

当用户阅读完一篇文章时上报 `complete` 反馈。

```javascript
// 使用 IntersectionObserver 检测用户是否阅读到文章底部
function setupReadCompletionTracker(userId, articleExternalId) {
	const articleEnd = document.getElementById('article-end');

	const observer = new IntersectionObserver(
		(entries) => {
			entries.forEach((entry) => {
				if (entry.isIntersecting) {
					submitFeedback(userId, articleExternalId, 'complete');
					observer.disconnect(); // 只触发一次
				}
			});
		},
		{ threshold: 0.5 }
	);

	observer.observe(articleEnd);
}
```

### 场景四："不感兴趣"按钮

```javascript
async function onNotInterested(userId, articleExternalId) {
	await submitFeedback(userId, articleExternalId, 'dislike');

	// 从当前列表中移除该内容
	removeCardFromFeed(articleExternalId);
	showToast('将减少此类推荐');
}
```

### 场景五：综合反馈面板

```javascript
class FeedbackPanel {
	constructor(userId, articleExternalId) {
		this.userId = userId;
		this.articleExternalId = articleExternalId;
	}

	// 点击
	trackClick() {
		debouncedClickFeedback(this.userId, this.articleExternalId);
	}

	// 点赞
	async like() {
		await submitFeedback(this.userId, this.articleExternalId, 'like');
	}

	// 阅读完成
	async complete() {
		await submitFeedback(this.userId, this.articleExternalId, 'complete');
	}

	// 不感兴趣
	async dislike() {
		await submitFeedback(this.userId, this.articleExternalId, 'dislike');
	}
}
```

## 7.6 反馈策略建议

### 必须上报的反馈

| 动作       | 优先级 | 理由                               |
| ---------- | ------ | ---------------------------------- |
| `like`     | 高     | 最强的正向信号，直接影响推荐质量   |
| `dislike`  | 高     | 唯一的负向信号，防止推荐不相关内容 |
| `complete` | 高     | 表示深度兴趣，权重最高             |
| `click`    | 中     | 弱正向信号，但量大时也有价值       |

### 上报时机建议

| 动作       | 上报时机                    | 注意事项                       |
| ---------- | --------------------------- | ------------------------------ |
| `click`    | 用户点击进入详情页时        | 防抖处理，快速滑动不上报       |
| `like`     | 用户主动点击点赞/收藏按钮时 | 即时上报                       |
| `complete` | 用户阅读到文章底部时        | 使用 IntersectionObserver 检测 |
| `dislike`  | 用户点击"不感兴趣"时        | 即时上报                       |

### 静默失败

反馈接口的失败**不应影响用户体验**。建议：

- 反馈请求使用 `try/catch` 包裹
- 失败时仅打印日志，不弹错误提示
- 可选：将失败的反馈存入本地队列，稍后重试

```javascript
// 静默反馈提交
async function silentFeedback(userId, documentId, action) {
	try {
		await submitFeedback(userId, documentId, action);
	} catch (err) {
		console.warn(`反馈提交失败 [${action}]:`, err.message);
	}
}
```
