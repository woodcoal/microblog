## ADR-M2-1：任务执行顺序调整

### 背景

M2 文档中 T1~T6 均依赖 M1-T3，彼此之间无显式依赖关系。但实际开发中存在隐含依赖和代码冲突风险：

- T2 评论系统需要评论点赞功能，依赖 Like 模型（T3 产出）
- T4 @提及与#标签 和 T5 可见度控制 都会修改发帖 API，连续开发减少冲突
- T5 可见度控制修改帖子查询逻辑，影响所有列表页，T6 搜索依赖可见度过滤

### 决策

调整执行顺序为：**T3 → T1 → T2 → T4 → T5 → T6**

| 顺序 | 任务            | 调整理由                                   |
| ---- | --------------- | ------------------------------------------ |
| 1    | T3 点赞与关注   | 先建 Like/Follow 模型，T2 评论点赞直接复用 |
| 2    | T1 文件上传     | 独立性强，不依赖其他 M2 任务               |
| 3    | T2 评论系统     | 复用 T3 的 Like 模型实现评论点赞           |
| 4    | T4 @提及与#标签 | 修改发帖 API 和 Markdown 渲染器            |
| 5    | T5 可见度控制   | 同样修改发帖 API，与 T4 连续开发减少冲突   |
| 6    | T6 搜索功能     | 依赖 T5 的可见度过滤逻辑，最后实现         |

### 影响

- 开发效率提升，减少重复修改同一文件
- 模型依赖关系清晰，避免中间态错误

## ADR-M2-2：Prisma Schema 一次性添加

### 背景

M2 涉及 8 个新模型（FileStorage, Media, Comment, Like, Follow, Tag, PostTag, Mention）和 Post/User 模型字段补全。模型间存在关联关系（如 Comment 关联 Like，Post 关联 Media/Comment/Like/PostTag/Mention）。

### 决策

一次性添加所有 M2 相关模型和字段，执行一次 migration。后续任务只编写业务逻辑代码，不再修改 schema。

具体变更：

**新增模型：**

- FileStorage（文件存储）
- Media（媒体附件）
- Comment（评论）
- Like（点赞）
- Follow（关注）
- Tag（标签）
- PostTag（帖子-标签关联）
- Mention（提及）
- UserSettings（用户设置，M2-T2 评论排序需要）

**Post 模型新增字段：**

- `passwordHash`（password 可见度用）
- `allowedUserIds`（users 可见度用，JSON 数组）
- `lockedBy`（锁定者 ID）
- `lockReason`（锁定理由）
- `deleteReason`（删除理由）
- `deletedBy`（删除者 ID）
- `restoreReason`（恢复理由）
- `restoredBy`（恢复者 ID）

**Post 模型新增关联：**

- media → Media[]
- comments → Comment[]
- likes → Like[]
- tags → PostTag[]
- mentions → Mention[]

**User 模型新增关联：**

- comments → Comment[]
- likes → Like[]
- followers → Follow[] @relation("UserFollowers")
- following → Follow[] @relation("UserFollowing")
- settings → UserSettings?
- mentions → Mention[]

### 影响

- 一次 migration 完成，避免分步添加产生中间态 schema 错误
- 后续任务专注业务逻辑，无需再改 schema
- 开发过程中如需调整字段，可追加 migration

## ADR-M2-3：提前创建 UserSettings 模型

### 背景

M2-T2 评论排序偏好需要持久化存储。SPEC 中 UserSettings 属于 M4 范围（含主题、API Token、Webhook 等设置项），但评论排序是 M2 的功能需求。

### 决策

M2 阶段即创建 UserSettings 模型，仅包含以下字段：

- `theme`：主题偏好（默认 "light"，M2 暂不实现主题切换，预留字段）
- `commentSortOrder`：评论排序偏好（默认 "asc"）

M4 阶段在此基础上扩展其他设置项。

### 影响

- M2 评论排序偏好可正确持久化
- 避免后续 M4 再添加模型和 migration
- 主题字段预留，M4 实现主题切换时直接使用

| 编号     | 决策                       | 选择理由                              |
| -------- | -------------------------- | ------------------------------------- |

| ADR-M2-2 | Schema 一次性添加          | 避免中间态错误，后续专注业务逻辑      |
