## M3-T1：仪表盘与用户管理

### 目标

实现管理后台布局、仪表盘统计和用户管理功能，使管理员能监控系统状态和管理用户。

### 步骤

1. 创建管理后台布局 `src/layouts/Admin.astro`：侧边栏导航
2. 实现 API：
    - `GET /api/admin/users`：用户列表（支持搜索、分页）
    - `PUT /api/admin/users/:id/disable`：禁用用户
    - `PUT /api/admin/users/:id/enable`：启用用户
3. 创建页面：
    - `src/pages/admin/index.astro`：仪表盘（统计数据 + 趋势图）
    - `src/pages/admin/users.astro`：用户管理
4. 仪表盘统计数据：总用户数、总帖子数、总评论数、总关注数、今日新增、30天趋势
5. 管理后台访问控制：检查用户 role = admin

### 效果

- 管理员访问 `/admin` 看到仪表盘，含统计卡片和趋势图
- 用户管理页可搜索、查看用户列表
- 可禁用/启用用户，禁用后用户帖子隐藏
- 非管理员访问 `/admin` 返回 403

### 验证

- 以管理员登录，访问仪表盘，统计数据正确
- 搜索用户，结果正确
- 禁用用户，该用户帖子从首页消失，评论显示提示词
- 启用用户，帖子恢复

## M3-T2：帖子与评论管理

### 目标

实现帖子管理（含删除/恢复/锁定/全局置顶）和评论管理，使管理员能全面管控内容。

### 步骤

1. 实现 API：
    - `GET /api/admin/posts`：全部帖子列表（含已删除）
    - `DELETE /api/admin/posts/:id`：删除帖子（需理由）
    - `PUT /api/admin/posts/:id/restore`：恢复帖子（需理由）
    - `PUT /api/admin/posts/:id/global-pin`：全局置顶/取消
    - `PUT /api/admin/posts/:id/lock`：锁定帖子（需理由）
    - `PUT /api/admin/posts/:id/unlock`：解锁帖子
    - `GET /api/admin/comments`：评论列表
    - `DELETE /api/admin/comments/:id`：删除评论
2. 创建页面：
    - `src/pages/admin/posts.astro`：帖子管理
    - `src/pages/admin/comments.astro`：评论管理
3. 管理员操作弹窗：删除/恢复/锁定需填写理由

### 效果

- 帖子管理页可搜索、查看所有帖子（含已删除）
- 管理员删除帖子需填写理由，理由记录在帖子数据中
- 管理员可恢复已删除帖子，需填写理由
- 全局置顶帖子出现在首页顶部
- 锁定帖子后不可编辑和评论
- 评论管理页可查看和删除评论

### 验证

- 管理员删除帖子，不填理由时提交失败
- 恢复已删除帖子，帖子重新出现在首页
- 全局置顶帖子出现在首页顶部
- 锁定帖子后，作者无法编辑，无法评论
- 管理员锁定的帖子，作者无法解锁

## M3-T4：通知系统

### 目标

实现站内通知的创建、展示和管理，使用户能及时获知社交动态。

### 步骤

1. Prisma schema 添加 Notification 模型
2. 在以下操作中自动创建通知：
    - 关注用户 → follow 通知
    - 评论帖子 → comment 通知
    - 点赞帖子/评论 → like 通知
    - @提及 → mention 通知
3. 实现 API：
    - `GET /api/notifications`：通知列表（分页）
    - `PUT /api/notifications/read`：标记已读
    - `GET /api/notifications/unread-count`：未读数量
4. 创建页面：
    - `src/pages/notifications.astro`：通知列表
5. 导航栏显示未读通知数量徽章

### 效果

- 被关注/评论/点赞/@时，导航栏通知数字更新
- 通知列表按时间倒序展示
- 可标记单条已读或全部已读
- 通知内容可点击跳转到相关帖子/用户

### 验证

- 用户 A 关注用户 B，用户 B 收到通知
- 用户 A 评论用户 B 的帖子，用户 B 收到通知
- 用户 A @用户 B，用户 B 收到通知
- 标记已读后，未读数字更新

## M3-T5：API Token 管理

### 目标

实现用户 API Token 的创建、管理和撤销，使第三方工具能通过 Token 访问 API。

### 步骤

1. Prisma schema 添加 ApiToken 模型
2. 编写 `src/lib/token.ts`：生成安全随机 token，存储 SHA-256 哈希
3. 实现 API：
    - `GET /api/tokens`：Token 列表（不返回明文）
    - `POST /api/tokens`：创建 Token（返回明文，仅此一次）
    - `DELETE /api/tokens/:id`：撤销 Token
4. 修改认证中间件：支持 JWT Token 和 API Token 双模式认证
5. 在个人设置页添加 Token 管理区域

### 效果

- 用户可在设置页创建 Token，设置名称
- 创建时显示明文 Token（仅一次），之后只显示哈希
- Token 列表显示名称、创建时间、最后使用时间
- 可撤销 Token
- API 请求可用 Token 替代 JWT

### 验证

- 创建 Token，复制明文
- 使用 Token 调用 API，成功返回数据
- 撤销 Token，再次调用 API 返回 401
- Token 最后使用时间正确更新

## M3-T6：Webhook 系统

### 目标

实现 Webhook 配置和事件推送，使用户能将站内事件同步到外部系统。

### 步骤

1. Prisma schema 添加 Webhook 模型
2. 实现 API：
    - `GET /api/webhooks`：Webhook 列表
    - `POST /api/webhooks`：创建 Webhook（生成 Secret）
    - `PUT /api/webhooks/:id`：更新 Webhook
    - `DELETE /api/webhooks/:id`：删除 Webhook
3. 编写 `src/lib/webhook.ts`：
    - `sendWebhook()`：构造 payload → HMAC-SHA256 签名 → HTTP POST
    - `triggerWebhooks()`：查询匹配事件的 Webhook → 逐一发送
4. 在通知创建后触发 Webhook
5. 在个人设置页添加 Webhook 管理区域

### 效果

- 用户可创建 Webhook，设置 URL 和触发事件
- 触发事件时，向 Webhook URL 发送签名请求
- 请求包含 HMAC-SHA256 签名
- 可启用/禁用 Webhook

### 验证

- 创建 Webhook，指向测试服务器
- 触发事件（如发帖），测试服务器收到请求
- 验证签名正确
- 禁用 Webhook 后不再收到请求
