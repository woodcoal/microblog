## M4-T1：热门排序算法

### 目标

实现热门时间线排序算法，支持管理员配置公式，使优质内容获得更多曝光。

### 步骤

1. 编写 `src/lib/trending.ts`：
    - 默认公式：`score = likes * w1 + comments * w2 + time_decay(hours)`
    - `time_decay`：指数衰减，越新权重越高
    - 支持从环境变量 `TRENDING_FORMULA` 读取自定义公式参数
2. 修改 `GET /api/posts`：热门时间线使用 trending score 排序
3. 创建页面：
    - `src/pages/latest.astro`：最新时间线（纯时间倒序）
4. 首页展示热门帖子，全局置顶帖优先

### 效果

- 首页按热门排序展示帖子，新帖不会完全淹没旧帖
- `/latest` 页面按纯时间倒序展示
- 管理员可通过修改 .env 中 TRENDING_FORMULA 调整公式参数改变排序效果
- 全局置顶帖始终在首页顶部

### 验证

- 发一条帖子获得多个点赞，该帖排名上升
- 管理员修改 .env 中 TRENDING_FORMULA，重启服务，排序效果变化
- `/latest` 页面严格按时间倒序

## M4-T2：主题系统

实现4种预置主题切换，偏好持久化，使用户能选择舒适的阅读体验。

5. 主题切换后：更新 UserSettings → 更新 CSS 变量 → 下次登录保持
6. 未登录用户：主题偏好存储在 localStorage

### 效果

- 导航栏有主题切换按钮
- 切换后页面样式立即变化
- 刷新后主题保持
- 登录用户跨设备同步主题偏好

## M4-T6：置顶与锁定完善

### 目标

完善置顶和锁定功能的边界情况处理，确保所有规则正确执行。

### 步骤

1. 实现 API：
    - `PUT /api/posts/:id/pin`：切换置顶（检查最大置顶数限制）
2. 置顶逻辑：
    - 检查环境变量 `MAX_USER_PINNED_POSTS`，为 0 时返回"置顶功能已关闭"
    - 已达上限时返回"置顶数量已达上限"
    - 管理员全局置顶同理检查 `MAX_GLOBAL_PINNED_POSTS`
3. 锁定逻辑：
    - 用户锁定：作者自己可锁定和解锁
    - 管理员锁定：需理由，用户不可解锁
    - 锁定后：编辑按钮隐藏、评论输入框隐藏、已有评论隐藏

### 效果

- 置顶数量达到上限时，置顶按钮禁用并提示
- 最大置顶数为 0 时（环境变量配置），置顶按钮不显示
- 管理员锁定的帖子，用户看不到解锁按钮
- 锁定帖子后，编辑和评论功能不可用

### 验证

- 置顶1条帖子（默认上限1），第2条帖子置顶按钮禁用
- 管理员设置 .env 中 MAX_USER_PINNED_POSTS=0，重启服务，置顶按钮消失
- 管理员锁定帖子，作者无法解锁
- 作者锁定帖子，作者可自行解锁
