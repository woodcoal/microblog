## ADR-M4-1：任务执行顺序调整

### 背景

M4 文档中 T1~T7 的顺序为 T1→T2→T3→T4→T5→T6→T7，但存在隐含依赖和效率问题：

- T3 操作记录需要在所有现有 API 中插入 `logActivity()` 调用，越早做后续改动越少
- T4 设置页依赖 T2 主题系统，必须在 T2 之后
- T5 SEO 依赖 T1 热门排序（首页分页需要排序逻辑就绪）
- T7 部署放最后，需要所有功能就绪

### 决策

调整执行顺序为：**T3 → T1 → T2 → T6 → T5 → T4 → T7**

| 顺序 | 任务              | 调整理由                                    |
| ---- | ----------------- | ------------------------------------------- |
| 1    | T3 操作记录       | 需在所有 API 中插入调用，越早做后续改动越少 |
| 2    | T1 热门排序       | 首页排序逻辑，SEO 分页依赖                  |
| 3    | T2 主题系统       | T4 设置页的前置依赖                         |
| 4    | T6 置顶与锁定完善 | 独立功能，与 T1 排序逻辑有关联              |
| 5    | T5 SEO 优化       | 依赖 T1 排序和 T6 置顶逻辑                  |
| 6    | T4 个人设置页     | 整合 T2 主题 + M3 的 Token/Webhook          |
| 7    | T7 API 文档与部署 | 所有功能就绪后最后处理                      |

### 影响

- 减少重复修改同一 API 文件
- 依赖关系清晰，避免回头改

## ADR-M4-2：热门排序公式策略

### 背景

SPEC 要求支持 `TRENDING_FORMULA` 环境变量配置热门排序公式。自定义公式解析存在安全风险和复杂度问题。

### 决策

**不做公式解析器**，使用 JSON 配置权重参数：

```json
{ "wLikes": 1, "wComments": 2, "decayHours": 24 }
```

排序公式：

```
score = likes * wLikes + comments * wComments * e^(-hours / decayHours)
```

- `wLikes`：点赞权重，默认 1
- `wComments`：评论权重，默认 2（评论比点赞更有价值）
- `decayHours`：时间衰减半衰期（小时），默认 24

环境变量 `TRENDING_FORMULA` 为空时使用默认值，非空时解析为 JSON 覆盖默认参数。

### 影响

- 避免公式解析安全风险
- 配置灵活度足够，可调整权重和衰减速度
- 实现简单，易于理解和调试

## ADR-M4-3：主题系统 CSS 变量方案

### 背景

SPEC 要求 4 种预置主题（Light/Dark/Eye-care/High Contrast），切换后持久化。

### 决策

1. **CSS 变量 + `data-theme` 属性**：在 `<html>` 标签上设置 `data-theme` 属性，通过 CSS 变量切换主题
2. **变量定义位置**：在 Base 布局的 `<style is:global>` 中定义 4 套变量
3. **持久化策略**：
    - 登录用户：写入 UserSettings 表，跨设备同步
    - 未登录用户：存储在 localStorage
4. **初始化**：Base 布局中内联一段 `<script>` 读取 localStorage 设置 `data-theme`，避免 FOUC（闪烁）
5. **ThemeSwitcher 组件**：React Island，下拉选择主题

### 影响

- 所有页面通过 CSS 变量统一控制颜色
- 切换即时生效，无需刷新
- 登录/未登录用户均有良好体验

## ADR-M4-4：API 文档手写 OpenAPI 方案

### 背景

SPEC 要求使用 Scalar 展示 API 文档。有两种方案：手写 OpenAPI JSON 或从代码自动生成。

### 决策

**手写 OpenAPI JSON**，理由：

- Astro API Routes 不方便集成 tsoa 等自动生成工具
- API 数量有限（约 40 个），一次性写完比折腾自动生成更实际
- 手写可精确控制描述、示例和分组

实现方式：

- 创建 `src/pages/api/docs.json.ts`：动态返回 OpenAPI JSON
- 创建 `src/pages/api/docs.astro`：Scalar 文档页面

### 影响

- API 文档精确可控
- 维护成本可接受（API 变更时同步更新 JSON）

## ADR-M4-5：部署适配器策略

### 背景

当前开发环境使用 `@astrojs/node` 适配器，生产部署目标为 Cloudflare Pages，需要 `@astrojs/cloudflare` 适配器。切换适配器可能影响开发环境。

### 决策

**开发环境继续使用 `@astrojs/node`，部署时通过环境判断切换适配器。**

在 `astro.config.mjs` 中根据 `CLOUDFLARE` 环境变量选择适配器：

```js
const adapter = process.env.CLOUDFLARE ? cloudflare() : node({ mode: 'standalone' });
```

### 影响

- 开发环境不受影响
- 部署时设置 `CLOUDFLARE=true` 即可切换
- wrangler.toml 配置 D1 和 R2 绑定
