# M6 百变 — 分类系统 + 多模式 + 收藏 + Actions 重构

> 里程碑代号：M6
> 核心目标：引入分类与多模式架构，使睦谈可按需变形为微博/论坛/博客；迁移到 Astro Actions；去除 React 依赖，回归原生 Astro 组件
> 前置依赖：M1-M5 全部完成
> 执行时间：2026-06

---

## 背景与动机

睦谈 M1-M5 已完成完整的微博功能闭环。但微博、论坛、博客在内容组织上有大量共性——用户、帖子、评论、互动——差异主要在**展示方式**和**编辑体验**。

通过引入**分类模式**概念，让一个站点同时支持多种内容形态：

- 微博频道：时间线消费，快速短文
- 论坛频道：版块浏览，结构化讨论
- 博客频道：文章阅读，长文写作

管理员通过 `SITE_MODES` 配置启用哪些模式，至少选一种。只选一种时等效于纯微博/纯论坛/纯博客。

同时，M6 将进行两项架构优化：

1. **API → Astro Actions**：内部交互从 `fetch('/api/...')` 迁移到 Astro Actions，获得类型安全和更简的代码
2. **React Islands → 原生 Astro**：去除 React 依赖，使用 Astro 原生组件 + Actions 实现交互

## 核心设计决策

### 决策 1：模式由分类决定，而非站点全局

每个分类（Category）携带 `mode` 字段（weibo/forum/blog），帖子发布时继承分类的模式。无分类的帖子默认为 weibo 模式。

**理由**：比全局 SITE_MODE 更灵活，一站可多形态混搭。

### 决策 2：帖子冗余存储 mode 字段

Post 表直接存储 `mode`，不通过 categoryId JOIN 推导。

**理由**：

- 无分类帖子也需要模式标识
- 首页混合时间线查询无需 JOIN
- 发布时写入，之后不变

### 决策 3：title 字段多语义

| mode  | title 含义    | 必填 |
| ----- | ------------- | ---- |
| weibo | 帖子摘要/简介 | 否   |
| forum | 帖子标题      | 是   |
| blog  | 文章标题      | 是   |

### 决策 4：发布入口绑定频道

在哪个频道页面下发布，就使用该模式的编辑器，帖子自动带该 mode。不提供跨模式发布。

### 决策 5：站点模式配置不可变

`SITE_MODES` 在 `.env` 中配置，建站时确定，运行期间不可更改。分类管理只能创建已启用模式的分类。

### 决策 6：现有 API 全部标记弃用

所有现有 `/api/` 路由标记为 `@deprecated`，M6 不再新增 API 路由（分类管理走 Actions）。API 路由将在后续里程碑中统一整理升级，当前仅保留不动。

### 决策 7：优先使用原生 Astro 组件

交互组件（点赞、关注、收藏等）使用 Astro 原生组件 + Astro Actions 实现，不再依赖 React Islands。仅博客富文本编辑器（Tiptap）因复杂度保留为 React Island。

**理由**：

- 减少客户端 JS 体积（无 React runtime）
- Astro Actions + `<form>` 天然支持渐进增强
- 代码更统一，维护更简单

## 页面结构

### 多模式启用时

| 页面       | 路由                  | 说明                                           |
| ---------- | --------------------- | ---------------------------------------------- |
| 大杂烩首页 | `/`                   | 混合时间线，三种模式帖子混排，卡片按 mode 渲染 |
| 微博频道   | `/weibo`              | 时间线 + 简单发布框                            |
| 论坛频道   | `/forum`              | 版块列表 → 帖子列表 + 结构化发布框             |
| 博客频道   | `/blog`               | 文章列表 + 富文本发布框                        |
| 个人主页   | `/@username`          | 按用户帖子 mode 分 tab                         |
| 内容详情   | `/@username/{postId}` | 根据 post.mode 渲染不同模板                    |

### 单模式启用时

`/` 直接重定向到该模式首页（如只启用 weibo → `/` 就是 `/weibo` 的内容），导航不显示频道切换。

## Schema 变更

### 新增表

#### Category（分类）

```prisma
/// 分类表 — 两级结构，一级为分组，二级为分类
model Category {
  id          String     @id @default(cuid())
  name        String     // 分类名称
  slug        String     @unique  // URL 友好标识
  mode        String     // weibo | forum | blog — 分类所属模式
  parentId    String?    // 父分类 ID（null = 一级分组）
  description String     @default("")  // 分类描述
  icon        String     @default("")  // 图标（emoji 或图标名）
  sortOrder   Int        @default(0)   // 排序权重
  postCount   Int        @default(0)   // 帖子数缓存
  createdAt   DateTime   @default(now())
  updatedAt   DateTime   @updatedAt

  parent      Category?  @relation("CategoryChildren", fields: [parentId], references: [id])
  children    Category[] @relation("CategoryChildren")
  posts       Post[]
}
```

#### Bookmark（收藏）

```prisma
/// 收藏表 — 用户收藏/书签帖子
model Bookmark {
  id        String   @id @default(cuid())
  userId    String   // 收藏者
  postId    String   // 被收藏的帖子
  createdAt DateTime @default(now())

  user      User     @relation(fields: [userId], references: [id])
  post      Post     @relation(fields: [postId], references: [id])

  @@unique([userId, postId])  // 每人每帖只能收藏一次
}
```

### Post 表新增字段

```prisma
model Post {
  // ... 现有字段 ...

  mode        String    @default("weibo")  // weibo | forum | blog — 帖子模式
  title       String?   // weibo=可选摘要, forum/blog=标题
  categoryId  String?   // 外键 → Category

  category    Category? @relation(fields: [categoryId], references: [id])
  bookmarks   Bookmark[]
}
```

### User 表新增关联

```prisma
model User {
  // ... 现有字段 ...

  bookmarks   Bookmark[]
}
```

## 站点配置

### 新增环境变量

| 环境变量     | 类型   | 默认值    | 说明                                                         |
| ------------ | ------ | --------- | ------------------------------------------------------------ |
| `SITE_MODES` | string | `"weibo"` | 启用的模式，逗号分隔，至少选一个。可选值：weibo, forum, blog |

### 读取方式

在 `src/lib/config.ts` 中解析：

```typescript
/** 解析启用的站点模式 */
const SITE_MODES = (import.meta.env.SITE_MODES || 'weibo')
	.split(',')
	.map((m) => m.trim())
	.filter((m) => ['weibo', 'forum', 'blog'].includes(m));

/** 是否启用某模式 */
const isModeEnabled = (mode: string) => SITE_MODES.includes(mode);

/** 是否为单模式站点 */
const isSingleMode = SITE_MODES.length === 1;

/** 单模式时的模式值 */
const singleMode = isSingleMode ? SITE_MODES[0] : null;
```

## 各模式行为差异

| 维度       | weibo          | forum                | blog                                          |
| ---------- | -------------- | -------------------- | --------------------------------------------- |
| 分类定位   | 可选话题       | 必选版块             | 文章栏目                                      |
| title 字段 | 可选摘要       | 必填标题             | 必填标题                                      |
| 编辑器     | 纯文本框       | 简易 Markdown 编辑器 | 所见即所得富文本（Tiptap，唯一 React Island） |
| 帖子卡片   | 内容为主       | 标题 + 回复数        | 标题 + 摘要 + 封面                            |
| 评论排序   | 时间倒序       | 热度+时间            | 时间倒序                                      |
| 用户主页   | 时间线         | 主帖 + 回帖          | 文章列表                                      |
| 首页布局   | 时间线         | 版块列表 → 帖子列表  | 文章卡片列表                                  |
| 导航项     | 首页/通知/我的 | 首页/版块/热门/我的  | 首页/分类/归档/关于                           |

## React → Astro 迁移方案

### 现有 React Islands

| 组件         | 用途          | 迁移方案                                            |
| ------------ | ------------- | --------------------------------------------------- |
| LikeButton   | 点赞/取消点赞 | Astro 组件 + `<form action={actions.toggleLike}>`   |
| FollowButton | 关注/取关     | Astro 组件 + `<form action={actions.toggleFollow}>` |
| PostEditor   | 微博发帖      | Astro 组件 + `<form action={actions.createPost}>`   |
| PostEditForm | 编辑帖子      | Astro 组件 + `<form action={actions.updatePost}>`   |

### 保留 React 的场景

仅 **BlogEditor**（Tiptap 富文本编辑器）保留为 React Island，因为：

- 所见即所得编辑器需要复杂的状态管理
- Tiptap 是 React 生态组件
- 仅 blog 模式加载，不影响其他模式

### 迁移后的交互模式

```
之前：Astro 页面 → React Island → fetch('/api/...') → API 路由 → prisma
之后：Astro 页面 → Astro 组件 + <form action> → Astro Actions → prisma
特例：博客编辑器 → React Island (Tiptap) → Astro Actions → prisma
```

### T6 文章编辑器（blog 模式）

## 技术风险与应对

| 风险                       | 影响           | 应对                                                |
| -------------------------- | -------------- | --------------------------------------------------- |
| 富文本编辑器体积大         | 首屏加载慢     | React Island 懒加载，仅 blog 模式加载               |
| 分类帖子数缓存一致性       | 数据不准       | 写入时更新 + 定时校准                               |
| 模式切换导致 UI 复杂度上升 | 维护成本高     | 抽取模式相关逻辑为独立组件，按 mode 条件渲染        |
| 首页混合时间线查询性能     | 多模式 JOIN 慢 | mode 冗余存储避免 JOIN，分页查询加索引              |
| Actions + React 去除范围大 | 回归风险       | 分批迁移，每批验证，API 路由保留作为回退            |
| ForumEditor 无 React       | 交互体验降级   | 用 `<script>` + 原生 DOM 实现工具栏和预览，够用即可 |

**API 路由保留价值**：供外部客户端（API Token 认证）使用，M6 不删除，仅标记弃用。
