从原型到上线：设计系统的取舍

花 花荣 @huayang · 2026 年 8 月 5 日 · 5 分钟阅读

真正难的不是把设计系统做出来，是决定什么不做。一套令牌越全，维护成本越高；越精简，覆盖场景越窄。本文记录我们在多模式社区产品里做的几个关键取舍。

1. 令牌层级：三层而非两层

我们用「语义令牌 → 主题令牌 → 原始值」三层。语义令牌（--ink、--surface）给组件用，主题令牌（--bg）由主题文件覆盖，原始值（#1a1a2e）只在主题定义里出现一次。

组件永远不直接引用颜色值，只引用语义令牌——这是让多主题成立的底线。

2. 断点：抄 Bootstrap

最初我们自定义了一套断点，结果每个页面都在踩不同的坑。后来直接采用 Bootstrap 5 的 576/768/992/1200/1400，团队心智成本立刻下降。容器宽度也跟随：540/720/960/1140/1320。

3. 什么不做

不做原子级 CSS 框架——项目用 UnoCSS 已经够了。不做暗色专属组件——同结构不同令牌。不做响应式字体缩放——rem 和 clamp() 只在标题用。

原型是 HTML 单文件，但令牌和断点体系与生产代码对齐，交付时前端可直接复用。
