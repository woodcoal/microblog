# 首页推荐体验规格（MT-87）

本规格补充 `home-c.html` 与当前 `/` 首页实现，定义登录新用户的推荐门面。它是下一阶段实现的视觉与交互验收基线；不改变现有推荐排序、服务端接口或用户关系。

对应交互原型：`docs/ux/home-recommendations.html`。

## 方向与信息层级

首页是 **Explore（探索）** 表面：全站动态仍是页面主轴，推荐是帮助用户从内容流进入社区的第二阅读轴，而不是独立的营销区或数据看板。

- 首屏及“正在被讨论”保留为最高优先级；推荐区位于其后，仅在已登录时出现。
- 推荐区标题使用“为你准备”，并以一句简短说明交代当前推荐依据。内容推荐占宽列，创作者推荐占窄列；窄屏按内容、创作者顺序单列堆叠。
- 每个内容条目必须有可见的推荐理由（如“与你关注的话题相近”“正在被讨论”“来自已选兴趣”），与标题/摘要、作者和互动信息分层显示。
- 创作者卡只提供“关注”这一个关系动作；不可自动关注，也不以“已关注”作为推荐卡的默认状态。
- 冷启动提示是非阻断的轻量面板：可选择兴趣、跳过或稍后设置。跳过时仍显示多样化热门内容；不应阻止浏览、发布或注册完成后的其它操作。

## 桌面与移动布局

| 视口       | 推荐区                                                  | 冷启动面板                         | 关键约束                                                     |
| ---------- | ------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------ |
| >= 1024px  | `minmax(0, 2fr) / minmax(280px, 1fr)`，与当前推荐区一致 | 内容列上方的横向紧凑面板；动作贴右 | 不扩大内容流到页面全宽；创作者卡每行 44px 头像、右侧关注按钮 |
| 768–1023px | 单列，内容在前、创作者在后                              | 面板动作换行但保持同一阅读顺序     | 不能让理由标签与按钮挤压标题                                 |
| < 768px    | 单列、左右 16px 页面内边距                              | 标签可换行；“跳过”保持可达         | 所有操作最小 44px；关注按钮整行或右对齐；不产生横向滚动      |

## 交互与状态

### 兴趣选择（仅冷启动）

1. 仅在登录且没有完成过兴趣选择的用户首访展示；标题说明“可跳过”。
2. 标签为多选切换按钮，按 Space/Enter 可操作，使用 `aria-pressed` 反映选中状态；选中 0 个也允许继续。
3. “开始看看”保存选择后关闭面板并刷新推荐理由；“跳过”关闭面板，不写入虚假的偏好；“稍后设置”保留为设置页入口（本期只定义，不要求实现）。
4. 不使用全屏阻断弹窗。用户切换频道或刷新页面前的未提交选择不应被误认为已保存。

### 内容与创作者推荐

- 两路请求独立加载、独立失败、独立重试；其中一路失败不能遮住另一路或主内容流。
- 加载中使用与最终行数、宽度相符的骨架；骨架容器标记 `aria-busy="true"`，状态文案置于 `role="status"`、`aria-live="polite"`。
- 空态保留标题与轻量解释，并给出“浏览全站动态”或“去发现频道”的普通链接；不显示虚构候选。
- 失败态说明数据暂时不可用，提供同区域“重试”按钮；失败不改变关注关系、不吞掉焦点。
- 点击内容卡到帖子详情；点击头像/名字到创作者主页；关注成功后该创作者从候选区平滑移除并播报“已关注 X”，失败则恢复可操作的“重试关注”按钮并显示文字错误。

## 数据契约

### 已有内容推荐数据

现有 `getRecommend` 返回：

| 字段                                                             | 用途                                               |
| ---------------------------------------------------------------- | -------------------------------------------------- |
| `id`、`title`、`content`、`mode`                                 | 详情链接、标题/摘要和频道标识                      |
| `user.id`、`user.username`、`user.displayName`、`user.avatarUrl` | 作者链接、头像和辅助文本                           |
| `tags[]`、`category`                                             | 生成可解释理由和标签；无匹配时可退化为“正在被讨论” |
| `likeCount`、`commentCount`、`createdAt`                         | 次级互动/新鲜度信息；不能取代理由                  |
| `visibility`                                                     | 已由服务端过滤；客户端不得用它伪造可见性判断       |

### 已有创作者推荐数据

现有 `getRecommendUsers` 返回：

| 字段                                                | 用途                                           |
| --------------------------------------------------- | ---------------------------------------------- |
| `id`、`username`、`displayName`、`avatarUrl`、`bio` | 个人资料与主页链接                             |
| `mutualFollowCount`、`followerCount`                | 解释理由：优先“X 位共同关注”，否则“活跃创作者” |
| `latestPublicPostAt`                                | 可选的新鲜度说明；不作为唯一推荐理由           |

### 后续实现需要新增的最小状态

| 名称                  | 类型/来源                                 | 用途                                 |
| --------------------- | ----------------------------------------- | ------------------------------------ |
| `recommendReason`     | 每个内容/创作者的短文本（服务端输出优先） | 让推荐可解释，避免客户端猜测排序逻辑 |
| `interestOnboarding`  | `unseen` / `skipped` / `completed`        | 控制非阻断冷启动面板是否展示         |
| `selectedInterestIds` | 用户持久化的 tag/category ID 数组         | 写入用户主动选择，供后续推荐使用     |
| `followState`         | `idle` / `pending` / `error` / `success`  | 防止重复关注，保证可恢复的失败反馈   |

`recommendReason` 可以在后端排序阶段生成；在其尚不可用前，前端只允许根据上述已有字段呈现保守文案（共同关注、标签相同、正在被讨论），不得声称不存在的行为数据。

## 视觉与无障碍验收

- 仅使用 `--color-*`、`--spacing-*`、`--radius-*` 和现有断点；不另设频道色、渐变或玻璃表面。
- 推荐理由为真实文本，不能只靠颜色或图标传达；正文、辅助信息和按钮在 light / dark / eye-care / high-contrast 主题下均保持可读。
- Tab 顺序遵循视觉顺序：兴趣标签 → 主操作/跳过 → 内容链接 → 创作者主页 → 关注。可见焦点环不移除。
- `aria-live` 只用于异步结果、关注成功和失败消息，避免初次渲染朗读整块推荐内容。
- 在 390 / 768 / 1024 / 1440px 验证 `scrollWidth <= clientWidth`、44px 触控目标和可读的两行以内推荐理由。
- 原型中的姓名、内容和数量均为界面示例，不代表真实用户、关系或推荐结果。

### 设计自检

按原型设计自检（反模式评分）为 **0/10**：未使用渐变、玻璃拟态、等权功能卡、虚构仪表盘或居中营销结构；主构图保持探索页的内容阅读节奏，层级由真实的内容、理由和动作承担。

## 实现拆分建议

1. 先在推荐 Action 的显示模型中补上保守的 `recommendReason`，并调整现有 `src/pages/index.astro` 的内容行与创作者卡层级。
2. 再增加兴趣偏好的读写契约与非阻断面板；无选择时保持现有多样化热门结果。
3. 最后补齐关注的 `pending/error/success` 可访问反馈，并依据本原型覆盖加载、空、失败和移动端回归。
